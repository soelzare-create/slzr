# از نقشهٔ DXF تا طرح چیدمان دسته‌کالا (روشِ ثبت‌شده)

برای وقتی مشتری فایل نقشهٔ فروشگاه (DXF) می‌دهد و «چیدمان استاندارد بر پایهٔ همین قفسه‌ها و یخچال‌ها»
می‌خواهد. دو نمونهٔ کامل: `scripts/layout/specs/raga_market.py` و `specs/yaran_sabz.py`.
خروجی استاندارد (سه چیز): فایل DXF با لایه‌های طرح، گزارش HTML خلاصه‌اول با نقشهٔ تعاملی، تصویر نقشه.

## ۱. فرمت فایل
DXF بخواه (نه DWG: ابزار خواندن نیست؛ نه PDF: لایه و بلوک ندارد). نسخهٔ AutoCAD 2018 DXF مناسب است.
RAR/ZIP را با `unar` باز کن (`apt-get install -y unar`). ابزارها: `pip install ezdxf matplotlib pillow`.
برای اجرا از `python3 -I` استفاده کن و اسکریپت‌ها را در پوشه‌ای جدا از فایل‌های دریافتی نگه دار.

## ۲. خواندن نقشه (`scripts/layout/dxf_tools.py`)
1. `inspect` ← واحد، لایه‌ها، بلوک‌ها، extents (موجودیِ دورافتاده می‌تواند extents را هزاران متر بکشد).
2. `grid plan.dxf out.png x0 y0 x1 y1 ppm` ← برش با شبکهٔ ۱ متری قرمز؛ مختصات را از همین تصویر بخوان.
3. `inserts` ← bbox واقعی هر تجهیز. **نقطهٔ درج را نخوان**، فقط bbox را.
4. نوشته‌های فارسی قدیمی (SHX) به‌صورت آشغال می‌آیند؛ نخوانشان. تجهیز را با نام بلوک، اندازه و جا بشناس:
   BSS/BSSD = قفسهٔ دیواری/سرقفسه، BDS = بدنهٔ گوندولا، BRV/BRD/BF = یخچال، ch200x110 = پیشخوان صندوق.
5. پیکان‌های سیاه کنار در = جهت ورود (به داخل) و خروج. ورود و خروج را از همین‌ها و فضای صندوق بخوان.
6. فرض‌های نامطمئن (مثلاً استند هاشورخورده) را در پاسخ به کاربر صریح بنویس.

## ۳. طراحی
اصول `store-layout.md` (§۲). ترتیب: مسیر پادساعتگرد از ورود ← تازه‌ها ← دیوار پشتی مقصد (لبنیات، منجمد) ← خوراکی خشک ←
بهداشتی/نظافت (جدا از خوراکی) ← تنقلات و سرو سرد ← صندوق. هر وجه قفسه و هر یخچال دقیقاً یک دستهٔ کالا.
- فقط اگر لازم است تجهیز جابه‌جا کن (نمونه: استند میوهٔ ورودی) و اگر نیست، صریح بگو «بدون جابه‌جایی».
- هر دسته یک **خانواده** (رنگ) دارد؛ رنگ‌ها از پالت اعتبارسنجی‌شدهٔ dataviz (`layout_common.FAM`).
- **گروه کالایی** = چند جایگاه همسایه با یک محوطهٔ رنگیِ ملایم دور آن‌ها و نام گروه روی نقشه.
- هر جایگاه کد دارد (حرف + عدد؛ وجه‌ها با W/E، سرقفسه‌ها با N/S) و روی نقشه «کد - نام» نوشته می‌شود؛ جایی که جا
  نیست (سرقفسه‌ها) فقط کد.
- اگر کاربر دسته‌ای را عوض کرد، فقط همان را عوض کن؛ مابقی را دست نزن. از آثار جانبی بگو (مثلاً چای کنار اسپری).

## ۴. ساخت
```bash
S=.claude/skills/merchandising/scripts/layout
python3 -I $S/dxf_tools.py grid  in.dxf grid.png 18 8 33 23 70      # بخوان، مختصات بگیر
# specs/<store>.py را بنویس (Z, SHORT, GROUPS, FLOW, SPINE, META)
python3 -I $S/layout_dxf.py    specs/<store>.py in.dxf out.dxf           # DXF با لایه‌های DX-*
python3 -I $S/dxf_tools.py base out.dxf base.png x0 y0 x1 y1 80          # همان برش META["crop"]
python3 -I $S/layout_report.py specs/<store>.py base.png outdir          # html + artifact + preview
```
قالب spec: `Z` فهرست `(کد, خانواده, چندضلعی, نام, نام انگلیسی, تجهیز)`؛ `SHORT` نام کوتاه روی نقشه؛ `GROUPS`
`(id, خانواده, نام, en, چندضلعی‌ها, (x,y) برچسب, چرخش, اعضا)`؛ `FLOW`/`SPINE` نقطه‌های مسیر؛ `META` متن‌ها، آمار، تصمیم‌ها
(`[[کد]]` لینک‌دوطرفه می‌شود)، مسیر، ایستگاه‌ها، درها، مکان راهنما، `moves`/`ghosts`. هر کد باید در یک گروه و یک ایستگاه باشد
(اسکریپت assert می‌کند).
لایه‌های DXF خروجی: DX-GROUP, DX-ZONE, DX-CODE, DX-FLOW, DX-OLD, DX-LEGEND؛ فونت Tahoma. با `ezdxf audit` بررسی کن، و
بگو که در اتوکد باز نشده.

## ۵. گزارش (خلاصه‌اول)
حکم ← آمار ← ۳-۴ تصمیم کلیدی ← مسیر مشتری ← نقشه (گروه‌ها، کدهای دوطرفه، نقطهٔ متحرک روی مسیر، محوطه‌ها با تپش) ←
فهرست جایگاه‌ها (تاشو). «ایرادهای نقشهٔ فعلی» و «فرض‌ها/فایل اتوکد» فقط اگر کاربر خواست. موشن با
`prefers-reduced-motion` خاموش می‌شود. تست: دسکتاپ و موبایل، روشن و تیره، بدون خطای کنسول.
